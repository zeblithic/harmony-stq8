# STQ8 ("Estiquate") — Speech-to-Q8 Design

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A per-user-calibrated speech recognizer that converts spoken Q8 syllables into Q8 bytes, with a "tome" (personal spellbook) that maps short Q8 addresses to meaningful actions and references.

**Repo:** `zeblithic/harmony-stq8` (standalone crate, Apache-2.0 OR MIT)

---

## 1. Q8 Encoding Recap

Each nibble (4 bits) maps to a consonant-vowel syllable:

| Bits | Consonant | Vowel |
|------|-----------|-------|
| 00   | ' (glottal stop) | O |
| 01   | J | U |
| 10   | K | E |
| 11   | V | I |

Two syllables = one byte. `10010010` = `KU'E`. `11111111` = `VIVI`.

8 words per line, space-separated. Newline every 64 bits.

## 3. Audio Pipeline & Feature Extraction

### Audio Capture (browser side, NOT in stq8-core)

- `AudioWorklet` processes mic input at 16kHz mono (downsampled from device rate)
- On PTT press: start streaming PCM f32 chunks to WASM module
- On PTT release: send end-of-utterance signal
- Frame size: 25ms (400 samples at 16kHz), hop size: 10ms (160 samples)

### Syllable Segmentation (in stq8-core)

1. **Energy-based onset detection** — track RMS energy per frame. Syllable starts when energy rises above threshold (relative to recent noise floor), ends when it drops back.
2. Each detected syllable gets windowed and passed to feature extraction independently.
3. Between syllables (silence/low energy), insert a boundary marker. Two consecutive syllables = one Q8 word.

### MFCC Extraction (in stq8-core)

For each syllable window:

1. Pre-emphasis filter (boost high frequencies)
2. Hamming window
3. FFT via `rustfft` (pure Rust, WASM-safe)
4. Mel filterbank (26 triangular filters, 300Hz–8kHz)
5. Log energy + DCT → 13 MFCC coefficients
6. Delta coefficients (first derivative across frames)

Output: ~52 floats per syllable (13 MFCCs × 2 stats (mean + variance) across frames).

## 4. Classifier & Calibration

### Classifier Trait

```rust
trait Classifier {
    fn classify(&self, features: &[f32]) -> (Phoneme, f32);
    fn train(&mut self, samples: &[(Phoneme, Vec<f32>)]);
}
```

### Primary: Nearest Centroid

- During calibration, compute mean feature vector per phoneme from user's samples
- At inference, cosine similarity against all 8 centroids
- Confidence = ratio of best-match distance to second-best (how much daylight between them)

### Upgrade Path: Tiny Feedforward Net

- 52 inputs → 32 hidden (ReLU) → 8 outputs (softmax)
- ~2K parameters, trainable from 32 calibration samples + augmentation
- Behind the same `Classifier` trait

### Calibration Ceremony (32 utterances)

**Phase 1 — Individual syllables (16):**

```
'O  'U  'E  'I
JO  JU  JE  JI
KO  KU  KE  KI
VO  VU  VE  VI
```

**Phase 2 — Transition words (16):**

Each first-syllable vowel paired with each second-syllable consonant:

```
'OJO  'UKO  'EVO  'I'O
JOJU  JUKU  JEVU  JI'U
KOJE  KUKE  KEVE  KI'E
VOJI  VUKI  VEVI  VI'I
```

Captures vowel→consonant coarticulation transitions.

### User Profile

```rust
UserProfile {
    centroids: [[f32; 52]; 8],       // 8 phoneme templates
    thresholds: {
        auto_accept: f32,             // default 0.85
        suggest: f32,                 // default 0.60
        reject_below: f32,            // default 0.40
    },
    custom_map: Option<HashMap<Phoneme, Phoneme>>,
    created: u64,
}
```

~2KB serialized. Portable across devices.

## 5. Confidence & UX Flow

### Three-Tier Confidence Model

```
  1.0 ┬─────────────────────────
      │   AUTO-ACCEPT
      │   Syllable recognized, emitted immediately
 0.85 ├─────────────────────────
      │   SUGGEST
      │   "Did you mean JOKU?"
      │   Tap to accept, or re-speak
 0.40 ├─────────────────────────
      │   REJECT
      │   Too ambiguous, no suggestion
      │   Brief shake/flash, "try again"
 0.0  ┴─────────────────────────
```

Thresholds per-user tunable. Accepted suggestions become implicit training data.

### Push-to-Talk Flow

1. User holds PTT button → "cast bar" appears (magenta-themed)
2. Syllables appear left-to-right as recognized
3. Complete words (2 syllables) get a subtle divider
4. Suggestions shown grayed, visually distinct from accepted syllables
5. User releases PTT → final Q8 bytes → tome lookup
6. Dangling odd syllable on release → discarded
7. Cast bar is an ARIA live region; PTT activates on Enter and Space

## 6. Tome & Scroll Data Model

### Zenoh Keyspace

```
harmony/{user_address}/tome/{q8_address} → scroll (≤4KB)
```

### Scroll Format

```rust
struct Scroll {
    version: u8,
    kind: ScrollKind,
    title: String,
    content: Vec<u8>,
    created: u64,
    updated: u64,
}

enum ScrollKind {
    Reference(CID),                 // points to content by CID
    Text(String),                   // inline text/note
    Alias(Vec<u8>),                 // redirects to another Q8 address
    Action { program: CID, args: Vec<u8> },  // recipe
}
```

### Address Collision Resolution (Power of Two Choices)

1. Hash content → 256-bit key
2. Derive two candidate short addresses (bits 0-3 and bits 4-7)
3. Place at whichever has fewer collisions
4. If both collide, extend to next nibble width and retry

~80% packing efficiency before needing wider addresses.

### Shortest-Prefix Resolution

Tome maintains a trie. Speaking `JO` checks:
- Unique prefix? → resolve immediately
- Multiple entries under `JO*`? → prompt with titles
- Nothing? → "No scroll at JO"

With ≤16 entries, one syllable (4 bits) usually suffices.

### PoC Scope

Tome stored as local JSON file. Zenoh keypath structure is real but publication is stubbed.

## 8. Graduation Path

## 9. Testing Strategy

### stq8-core Unit Tests

- **q8.rs:** nibble↔syllable roundtrip (all 16 values), byte↔word roundtrip, XOR checksum padding
- **mfcc.rs:** known sine wave → expected FFT bins, known spectrum → expected mel filterbank, pre-emphasis correctness, determinism (same input → same output)
- **segmenter.rs:** silence → no syllables, single burst → one syllable, two bursts with gap → two syllables, continuous energy → graceful handling. All synthetic PCM.
- **classifier.rs:** train with known centroids → correct classification, equidistant → low confidence, exact match → high confidence, empty profile → error not panic, custom remapping
- **profile.rs:** serialize↔deserialize roundtrip, version compatibility
- **tome.rs:** scroll CRUD, collision resolution, shortest-prefix trie, address width extension

### Svelte Component Tests (vitest)

- CastBar renders syllables, distinguishes accepted vs suggested
- CalibrationWizard progresses through 32 utterances
- TomeBrowser displays scroll contents
- PTT button accessible (Enter + Space, ARIA live region)

### Integration (manual for PoC)

- Record all 16 syllables → verify classification
- Speak 2-word address → verify tome lookup
- Speak ambiguously → verify suggestion appears
- No real-audio tests in CI — synthetic PCM only
